# 评测方法与复现

## 实验单位

一次实验冻结数据集摘要、选中样本、模型配置、提示词版本、拆分、样本上限和并发数。每个模型处理同一组样本；**模型按选择顺序执行，同一模型内按配置并发**。不同实验可同时运行，但共享全局调用上限，所以严肃性能比较应一次只运行一个实验，并停止手动调用等干扰。

采样使用选中拆分的前 N 条，而非随机抽样。默认 30 条、test 分组、并发 1；完整内置 test 集为 64 条。可通过 `max_samples=64` 运行完整 test 集。记录里的 `total` 是模型数乘实际选中行数，不一定等于配置的样本上限乘模型数。

本版不自动预热。第一次请求可能包含模型加载和冷启动；报告环境信息明确标记无预热。若要测热启动，请先在体验台进行一次调用，记录预热步骤，再开始实验。模型服务硬件、量化格式和上游服务版本不会自动探测，需要实验者补充。

## 指标定义

| 指标 | 定义 |
| --- | --- |
| `success_rate` | 得到有效结构化输出的请求数 / 已完成请求数 |
| `valid_output_rate` | 通过完整输出 JSON 校验的请求比例；本版与 success_rate 相同 |
| `field_accuracy` | 8 个提取字段的匹配总数 /（已完成请求数 × 8） |
| `category_accuracy` | 类别正确数 / 已完成请求数 |
| `macro_f1` | mechanical、electrical、software、other 四类 F1 的算术平均 |
| `p50_latency_ms` / `p95_latency_ms` | 成功请求耗时的 50% / 95% 分位数，排序后线性插值 |
| `throughput_rps` | 已完成请求数（包括失败）/ 相应执行计时窗口秒数 |
| `errors` | 按错误代码计数 |

字符串匹配做 Unicode NFKC 规范化、忽略大小写、合并连续空白并去掉两端空白。它不是语义匹配：同义改写、不同的产线命名或症状重述可能被判错。数字字符串不等于数字；`null` 只有在输出显式包含该字段且为 `null` 时得分。一个失败请求所有字段及分类均记 0 分，即使其标准答案有空值。

分类混淆矩阵的行是真实类别，列是预测类别，另有 `__error__` 列记录调用或格式失败。某个类别在样本中未出现且没有对应预测时，其 F1 记为 0；小样本只含部分类别时，不应把宏平均 F1 与覆盖四类的实验直接比较。

P50/P95 只统计成功请求，没有成功请求时返回 `null`，页面显示空值。它们是客户端调用到输出校验完成的耗时，不含实验排队、网关全局并发等待，也不包含数据库写入和浏览器渲染。当前没有流式调用，所以不报告首 token 延迟。吞吐使用实测执行时间，不能通过单请求延迟倒数推算；多模型整体吞吐也不应被当成任一模型的性能。

总体指标可包含规则服务与真实服务，只用于实验完整性核对。选型请分别查看逐模型结果，并明确其是否为模拟服务。

## 输出与错误

输出必须是完整 JSON 对象且只有约定的 9 个字段。非法 JSON、Markdown 包裹、缺字段、多字段、错误类型或非法类别计为 `invalid_output`。第一版不自动修复输出、不自动重试，方便观察原始接口行为。

| 错误代码 | 含义与排查方向 |
| --- | --- |
| `timeout` | 上游超过调用截止时间；检查模型冷启动、负载和超时配置 |
| `connection_error` | 无法连接服务；检查监听地址、端口和容器网络 |
| `upstream_error` | 上游返回非成功 HTTP 状态；检查模型名称和服务日志 |
| `invalid_output` | 输出或上游响应不符合结构要求；检查服务兼容性和模型回答 |
| `configuration_error` | 主机未授权、地址无效或密钥环境变量缺失 |

健康检查通过只能说明相应服务检查项通过，不代表工单提取质量或完整推理链路已验收。真实模型接入后，先手动试调用，再执行批量评测。

## 故障复现演示

在模型中心新建 provider 为 `demo` 的模型，依次测试以下故障模式。故障注入只用于 Demo 服务。

| 模式 | 预期用途 |
| --- | --- |
| `none` | 规则提取正常流程 |
| `noisy` | 确定性扰动部分输出；产生可复现质量差异 |
| `timeout` | 验证超时响应、失败记录及成功率下降 |
| `invalid_json` | 验证格式校验拒绝不合格输出 |
| `error` | 验证上游异常处理与错误分类 |

运行同一份数据对比 `none` 与 `noisy`，检查逐行差异。再单独运行超时/格式故障，确认失败项无字段得分。恢复配置后重新运行；新实验使用新配置，旧实验快照保留原值。

取消、中断或失败实验的报告只统计已有结果；未执行样本不进入分母。请同时查看状态、计划总数和完成数，不能把部分完成实验当作完整验收。硬中断可能来不及保存当前模型的计时，因此中断实验的吞吐显示为不可用，不将停机时间混入性能测量。服务重启不会自动重放中断任务。

## 真实模型报告应补充的信息

1. 模型名称、权重版本或哈希、量化格式、上下文长度、推理引擎与版本。
2. 模型服务器硬件、显存/内存、操作系统；与 API 主机分开记录。
3. 数据集 SHA-256、拆分、样本数、提示词版本、temperature、max_tokens。
4. 并发数、超时、是否预热、测试时间段以及同时发生的其他负载。
5. 自动报告、原始 JSON/CSV、关键失败样本与人工复核意见。

报告保存 API 主机的基础环境信息，但不会自动知道远端 GPU、权重实际版本或推理服务内部排队时间。资源面板的 CPU/RSS 只属于 API 进程；Prometheus 数据自本次进程启动以来累计，SQLite 历史数据则可跨重启保留。

## 结论边界

第一版帮助你建立可追踪的实验流程。它没有商业验收门槛、统计置信区间、语义评分或维修安全评估。模型选择应基于经授权、独立整理并人工复核的真实任务样本；不要用默认合成数据的高分宣布可直接投入产线。
